# صيدلية عز الصحة — نظام متابعة طلبات العملاء

نظام Flask لمتابعة طلبات العملاء والنواقص والمتابعات، مع واجهة ويب عربية.

## التخزين: محلي أو سحابي

يدعم المشروع مسارين فعليين من خلال واجهة قاعدة بيانات واحدة يستخدمها `app.py`:

### الوضع المحلي
اترك متغير البيئة `DATABASE_URL` **غير مضبوط**.

- التخزين التشغيلي: Excel داخل مجلد البيانات المحلي.
- المستخدمون: SQLite داخل مجلد البيانات المحلي.
- التشغيل على Windows: شغّل `run.bat`.
- الوصول من أجهزة أخرى على نفس الشبكة: افتح عنوان IP لجهاز الصيدلية والمنفذ 5000.
- هذا هو الوضع المناسب عندما تريد أن تبقى البيانات على جهاز الصيدلية.

### الوضع السحابي
اضبط `DATABASE_URL` على اتصال PostgreSQL قبل التشغيل/النشر.

- التخزين التشغيلي: PostgreSQL عبر `CloudDB`.
- المستخدمون: جدول `users` في PostgreSQL.
- Render: استخدم `render.yaml` كنقطة النشر الوحيدة.
- `SECRET_KEY` و`ADMIN_USERNAME` و`ADMIN_PASSWORD` أسرار بيئية ولا تُحفظ في المستودع.

**قاعدة الاختيار:** إذا كان `DATABASE_URL` موجودًا يستخدم النظام `CloudDB`، وإذا لم يكن موجودًا يستخدم `ExcelDB`. لا توجد حاجة لاختيار backend من `app.py` يدويًا.

## الأمان

- جميع كلمات المرور الجديدة تُخزّن باستخدام Argon2id.
- كلمات المرور القديمة بصيغة PBKDF2-SHA256 تُقبل فقط عند تسجيل الدخول الناجح ثم تُرقّى تلقائيًا إلى Argon2id.
- حماية CSRF موحدة للـPOST/PUT/PATCH/DELETE باستخدام session token و`X-CSRF-Token`.
- العمليات الإدارية الحساسة محمية على مستوى الخادم، وليس الواجهة فقط.
- بيانات الأخطاء العامة لا تعيد تفاصيل الاستثناء الداخلية إلى المستخدم؛ التفاصيل تُسجّل على الخادم عند الحاجة.
- أرقام جوالات العملاء تُعامل كبيانات حساسة ولا ينبغي وضعها في رسائل log أو debugging غير ضرورية.

## الصلاحيات

الحسابات نوعان:

- **مدير (admin):** إدارة المستخدمين، النسخ الاحتياطية والاستعادة، حذف كل البيانات، التصدير الحساس، وسجل التدقيق.
- **موظف (employee):** العمليات التشغيلية على الطلبات والعملاء والنواقص، وفق وظائف النظام الحالية.

سياسة الموظف التشغيلية لا تعتمد على إخفاء الأزرار في الواجهة؛ التحقق من المسارات الحساسة يتم على الخادم.

## التشغيل المحلي

1. ثبّت Python 3.
2. ثبّت الاعتمادات:
   `py -3 -m pip install -r requirements.txt`
3. شغّل `run.bat`.
4. افتح `http://127.0.0.1:5000`.

## التشغيل على Render

`render.yaml` هو ملف النشر المعتمد. أمر التشغيل يستخدم Gunicorn مباشرة:

`python -m gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120`

لا تستخدم ملفات تشغيل بديلة لتفعيل Auth أو قاعدة البيانات؛ تهيئة التطبيق أصبحت داخل `app.py`.

## متغيرات البيئة

راجع `.env.example`.

- `DATABASE_URL`: اختيار CloudDB.
- `SECRET_KEY`: مفتاح جلسات Flask.
- `ADMIN_USERNAME` و`ADMIN_PASSWORD`: bootstrap لإنشاء حساب المدير الأول فقط؛ تغيير كلمة المرور من النظام يبقى محفوظًا بعد ذلك.
- `OPENAI_API_KEY` و`OPENAI_MODEL`: خدمات المساعد، عند استخدامها.

## الترقية والترحيل

ترقية كلمات المرور تتم lazy migration عند أول تسجيل دخول ناجح. لا يحتاج المستخدم إلى معرفة الـhash القديم.

عند الانتقال من الوضع المحلي إلى السحابي، يجب استخدام وظيفة استيراد البيانات الموجودة في النظام ومراجعة النسخة الاحتياطية قبل الاعتماد النهائي على البيانات.

## الملفات الرئيسية

- `app.py`: نقطة الدخول ومسارات HTTP وتهيئة extensions.
- `db.py`: اختيار backend وتثبيت الواجهة الموحدة.
- `cloud_db.py`: تنفيذ PostgreSQL.
- `auth/`: المصادقة وhashing وCSRF والسياسات.
- `data_export.py`: تصدير Excel الموحّد.
- `postrollback_export.py`: تصدير PostgreSQL الإضافي ومسارات العملاء المميزين.
- `render.yaml`: إعداد Render المعتمد.

## ملاحظات على البيانات

النسخ الاحتياطية والاستيراد والاستعادة تغيّر بيانات تشغيلية فعلية. راجع دائمًا اسم النسخة ووقت إنشائها قبل الاستعادة.
